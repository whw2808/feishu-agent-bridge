Validated locally on 2026-10-12: macOS 26.6.2 arm64, Python 3.14.6, native Codex 0.162.0, Python Codex SDK 0.162.1 and lark-cli 1.0.76. Credentials, group history, message IDs and session IDs are retained only in private local evidence, not distributed with the source or plugin.

## Automated checks

50 tests passed, with zero failures, errors or skips; Ruff passed. Checks exercise real SQLite persistence, CLI subprocesses and a fresh stdio MCP session, with controlled network/model fixtures. Coverage includes configured scope, identity mappings, edits during inference, immutable task versions, pagination recovery, full-queue cancellation, uncertain writes, reply validation, chunk fairness, acknowledgements, completed-task idempotency and clean plugin staging.

The structured report is generated by `python scripts/check.py` in ignored `.artifacts/check-report.json`; it records the exact Git head, dirty state, Python/platform and individual failures. Outside a Git checkout, head/dirty are explicitly null. A report made before a source change is not evidence for a later head.

An independent reviewer checked the first candidate and identified six Important findings plus one fairness finding initially graded Minor. All seven were fixed, fairness was treated as Important, and eleven new tests produced assertion failures before the fixes and passed afterwards. Live acceptance exposed two further issues: a pre-activation non-own parent could strand a current reply, and native plugin installation could copy a development worktree. Four additional assertions failed before those fixes and passed afterwards; a cross-group/message-ID rejection case also passed. No review findings were silently waived.

## Live acceptance

- A real background SDK call completed in 12.52 seconds on a separate thread, with no primary-session reuse and no external action requested.
- An authorized incoming true @ from another bot was read by the background worker and answered once in its original thread. Feishu readback confirmed the original parent/group and the recipient's actual application-scoped open ID.
- During that model job, nine real history reads completed concurrently. The background run took 16.92 seconds including read/send verification; it created no primary handoff. This verifies collection continues during inference, rather than relying only on mocked concurrency.
- The local user service connected to events and read history. Stopping its own instance took 0.159 seconds and its owned native event process exited; the shared event bus was not stopped. Restart and package upgrade preserved the SQLite state.
- Two current replies whose parent predates activation were released and read by the real background worker using verified parent identity only. Neither generated an unsolicited reply or primary task. Historical non-own content remains outside the requested reading boundary.

Private evidence includes `sdk-live-proof.json`, `live-acceptance.json`, `service-start-proof.json`, `service-stop-proof.json`, and installation checks under ignored `.artifacts/`. These records contain personal routing information and are intentionally absent from releases. Live tests are not rerun automatically by CI and must not send duplicate test responses.

## Limits

- GitHub CI covers Ubuntu/macOS with Python 3.11/3.13 as recorded above. Real Feishu/model operation and service lifecycle were tested locally on macOS; the Linux systemd service was not exercised live.
- This release supports macOS/Linux and Codex 0.162.x. Windows and other agent hosts are not validated or supported yet.
- All new messages since the configured activation/backfill boundary are collected and queued for reading. A creation-time scan with a 60-second overlap does not guarantee discovery of edits to older messages outside that window. Attachments are metadata only.
- The model cannot write project files or send directly. Deterministic guards reject known unverified completion-claim patterns; they are conservative checks, not a proof of arbitrary natural-language truth. Primary owners must report verified results.
- Network delivery is not promised exactly once. Ambiguous acceptance remains `uncertain` for manual reconciliation. Rate/model budgets can increase backlog; sleeping/offline machines cannot infer until resumed.
- Automatic data-retention cleanup, hosted operation, public PyPI publication and public plugin-directory submission are outside this release.
